### CHAPTER 3.0 UP (Unified Process)
---

START
Basic
Front: Che cos'è il UP ? 
Back: Unified Process è un processo **iterativo** e **incrementale** per lo sviluppo del software per la costruzione di sistemi orientati agli oggetti. Le iterazioni iniziali sono guidate dal rischio, dai casi d'uso e dall'architettura.

END

Basic
Front: Che cosa si viene a produrre in ogni fase di sviluppo?
Back: In ogni fasi di sviluppo si viene a produrre delle **Milestones**
<!--ID: 1757056975900-->
END

START
Basic
Front: Che cos'è una **Milestone**?
Back: Le milestone sono l'insieme di obbiettivi che si sono raggiunti durante una fase di sviluppo, che andranno ad addizionarsi al ciclo di vita del nostro progetto, come dei punti di salvataggio, dove si svolgono le decisioni più importanti del team.
<!--ID: 1757241583552-->
END

START
Basic
Front: Che cos'è una **Fase**?
Back: Una **Fase** viene intesa come l'insieme degli obbiettivi o dei macro-obbietti da dover raggiungere, in modo che, se per ogni fase si raggiungono gli obbiettivi che si sono imposti, si può passare a quella successiva, la **Fase varia in base al progetto che si sta sviluppando** o **del team che ci lavora sopra**
<!--ID: 1757057200098-->
END

Basic

Back: Il processo di sviluppo è suddiviso **in quattro fasi**, dove ad ognuna di loro, si viene a produrre dei semi lavorati chiamati **Milestone**

Back: Ogni fase all'interno possiedono delle iterazioni, dove ognuna di loro ci saranno delle attività che si potranno svolgere tutte oppure no.

### Iterazioni
---
START
Front: Che cos'è lo **sviluppo iterativo**?
Back: Lo **sviluppo iterativo**  è un approccio dell'UP, basato sullo sviluppo di una serie **di mini-progetti,** che avranno un tempo ben definito, che prendono il nome di **iterazioni**, cioè un prodotto software funzionante ma parziale.
END

START
Basic
Front: Che cos'è un'**iterazione**?
Back: L'**iterazione** nel contesto del processo di sviluppo software sarebbero  dei cicli ripetuti delle seguenti attività: pianificare, progettare, sviluppare, test e valutazione finale.
<!--ID: 1757059164413-->
END

START
Basic
Front: Quali sono le attività che vengono svolte in un'**iterazione**?
Back: Le attività svolte in un'iterazione sono:
- Pianificazione
- Analisi e Raccolta dei requisiti
- Progettare
- Implementare
- Integrazione e Test
- Validare e infine rilascio Interno o esterno
<!--ID: 1757062609572-->
END

START
Basic
Front: Quant'è la durata consigliata di **un iterazione**? 
Back: La durata di un'iterazione varia tra le 2 alle 6 settimane, della quale avremmo svolto le varie attività richieste.
<!--ID: 1757062609576-->
END

### Fondamenti del UP
---
START
Basic
Front: Cosa vuol dire **GUIDATO DAL RISCHIO**?
Back: Guidato dal rischio vuol dire che nello sviluppo del nostro progetto si possono incorrere a dei rischi di qualsiasi natura, in cui però grazie ad un'attenta  valutazione se ne possono ridurre le cause
<!--ID: 1757062609578-->
END

START
Basic
Front: Quali sono le fasi per **alleviare il rischio**?
Back: Per alleviare il rischio o rimuoverlo completamente andremmo a:
- Identificare i rischi che si possono incorrere durante le varie fasi di sviluppo.
- Prevenire il rischio, cioè pianificare il modo di evitarlo.
- Gestione del rischio, dove andremmo a metter mano nei rischi di maggior rilevanza.
<!--ID: 1757062609580-->
END


START
Basic
Front: Cosa vuol dire **GUIDATO DAI CASI D'USO**?
Back: Nel processo di sviluppo software, quando parliamo di un processo
**GUIDATO DAI CASI D'USO**, si intendono che si parte dal diagramma dei casi d'uso *(use-case)*, si identificano gli attori e le interazioni che svolgono nel sistema, alla fine di ciò si andrà a definire i **requisiti** che bisogna soddisfare, creando un prodotto che rispetti le esigenze del cliente.
<!--ID: 1757063590477-->
END

START
Basic
Front: Cosa vuol dire **INCENTRATO SULL'ARCHITETTURA**?
Back: Nel UP quando trattiamo di un **processo incentrato sull'architettura**, vuol dire che andremmo a dare maggior enfasi nella **disciplina della progettazione**, dando una maggior attenzione nello sviluppo di quest'ultimo perché parte critica del progetto.

Andando a creare diversi modelli UML per definire i requisiti necessari e la codebase del nostro sistema.
<!--ID: 1757063590480-->
END

START
Basic
Che cos'è un **Architettura**?
Back: L'architettura sarebbe l'insieme dei modelli UML, che ci rappresentano la struttura, la base dell'interno sistema, definendo anche i requisiti che deve soddisfare.
<!--ID: 1757237677761-->
END

START
Basic
Che cos'è un **incremento**?
Back: L'incremento o detto anche processo incrementale, consiste nel prendere un progetto da svolgere e suddividerlo in pezzi, dove dal primo pezzo che andrà a creare si aggiungerà in successione, delle copie di quest'ultimo, ma con delle migliorie o modifiche da quelle precedenti.
<!--ID: 1757238200354-->
END


START
Basic
Com'è suddivisa ogni **Fase**?
Back: La fase è suddivisa in ben quattro categorie: **Ideazione**, **Elaborazione**, **Costruzione** e **Transizione**.
<!--ID: 1757238200357-->
END

## Discipline

START
 Front: Che cos'è una **disciplina** nel UP?
 Back: Una disciplina sarebbe le attività che vengono ad essere svolte e i relativi elaborati che si producono da le seguenti attività, esempio l'analisi dei requisiti.
END 
START

Basic

Front: Che cos’è un incremento nel modello UP?

Back: È il risultato complessivo delle iterazioni; ogni incremento aggiunge nuove funzionalità al sistema, producendo una versione funzionante anche se parziale.
<!--ID: 1757242838788-->
END

  

START

Basic

Front: Qual è la differenza tra iterazione e incremento?

Back: L’iterazione è un ciclo di analisi, progettazione, realizzazione e validazione; l’incremento è l’insieme dei risultati di più iterazioni che produce un sistema funzionante più completo.
<!--ID: 1757242838790-->
END

  

START

Basic

Front: Qual è l’obiettivo della fase di Ideazione (Inception)?

Back: Analizzare la fattibilità del progetto, definire il **Business Case** e valutare i rischi principali.
<!--ID: 1757242838791-->
END

  

START

Basic

Front: Quali strumenti si usano nella fase di Ideazione (Inception)?

Back: Modelli dei casi d’uso, analisi preliminare dei requisiti, pianificazione iniziale, valutazione dei rischi.
<!--ID: 1757242838792-->
END

  

START

Basic

Front: Qual è la milestone della fase di Ideazione?

Back: **Lifecycle Objective Milestone**: se non sono definiti business case e rischi principali, il progetto va abbandonato o ridefinito.
<!--ID: 1757242838793-->
END

  

START

Basic

Front: Quanto deve durare la fase di Ideazione?

Back: Non più di una settimana; se dura di più significa che si è scesi in una specifica troppo dettagliata, in contrasto con lo spirito iterativo dell’UP.
<!--ID: 1757242838794-->
END

  

START

Basic

Front: Qual è l’obiettivo della fase di Elaborazione?

Back: Creare una baseline architetturale eseguibile, perfezionando i requisiti e riducendo i rischi.
<!--ID: 1757242838795-->
END

  

START

Basic

Front: Quali strumenti si usano nella fase di Elaborazione?

Back: Diagramma di analisi del dominio, progettazione dell’architettura e definizione della struttura complessiva del sistema.
<!--ID: 1757242838796-->
END

  

START

Basic

Front: Qual è la milestone della fase di Elaborazione?

Back: **Lifecycle Architecture Milestone**: completata se i casi d’uso sono all’80%, l’architettura è descritta ed eseguibile, i rischi e il business case rivisti e la pianificazione aggiornata.
<!--ID: 1757242838797-->
END

  

START

Basic

Front: Qual è l’obiettivo della fase di Costruzione (Construction)?

Back: Sviluppare il prodotto a partire dalla baseline architetturale fino a una prima beta completa e funzionante, pronta al beta-test.
<!--ID: 1757242838798-->
END

  

START

Basic

Front: Qual è la milestone della fase di Costruzione?

Back: Initial Operational Capability: prima versione completa con le funzionalità implementate e periodo di beta-testing.
<!--ID: 1757242838799-->
END

  

START

Basic

Front: Qual è l’obiettivo della fase di Transizione (Transition)?

Back: Rifinire e completare il prodotto, correggere i bug, distribuire il sistema agli utenti finali fino al rilascio definitivo.
<!--ID: 1757242838800-->
END

  

START

Basic

Front: Qual è la milestone della fase di Transizione?

Back: Product Release: rilascio del prodotto finito e completo che rispetta i requisiti iniziali.
<!--ID: 1757242838801-->
END

  

START

Basic

Front: Che cos’è una disciplina nel Unified Process?

Back: È l’insieme delle attività e degli elaborati in una determinata area (es. modellazione del business, requisiti, progettazione).
<!--ID: 1757242838802-->
END

  

START

Basic

Front: Che cos’è un elaborato nel Unified Process?

Back: Qualsiasi artefatto prodotto durante lo sviluppo: codice sorgente, diagrammi, documenti, schemi DB.
<!--ID: 1757242838803-->
END

  

START

Basic

Front: Quali sono le tre discipline principali considerate nel progetto?

Back: 
1. Modello di business (modello di dominio). 
2. Requisiti (casi d’uso e specifica supplementare). 
3. Progettazione (modello di progetto, architettura e interazioni software).
<!--ID: 1757242838804-->
END

  

START

Basic

Front: Cosa si intende per requisiti funzionali e non funzionali?

Back: 
- Funzionali = cosa deve fare il sistema.
- Non funzionali = vincoli sui componenti come prestazioni, usabilità e aspetti tecnici.
<!--ID: 1757242838805-->
END

  

START

Basic

Front: Quali discipline prevalgono nella fase di Ideazione (Inception)?

Back: Modello di Business e Requisiti; con una progettazione grossolana dell’architettura.
<!--ID: 1757242838806-->
END

  

START

Basic

Front: Quali discipline prevalgono nella fase di Elaborazione?

Back: Requisiti (quasi completati), Progettazione (baseline architetturale), prime implementazioni.
<!--ID: 1757242838807-->
END

  

START

Basic

Front: Quali discipline prevalgono nella fase di Costruzione?

Back: Implementazione e Test.
<!--ID: 1757242838808-->
END

  

START

Basic

Front: Quali discipline prevalgono nella fase di Transizione?

Back: Deployment e Project Management (rilascio del prodotto e correzione dei problemi).
